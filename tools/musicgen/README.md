# musicgen

Generates the game's background music as Standard MIDI files. 28 tracks: 8 wired
to maps, 20 unassigned alternates and extra themes kept for auditioning.

```bash
node tools/musicgen/build.mjs                 # render every track to public/mfx/
node tools/musicgen/preview.mjs               # render WAVs you can listen to
node tools/musicgen/preview.mjs title town    # ...just these
node --test "tools/musicgen/**/*.test.mjs"    # the suite
```

## Why MIDI

The client already plays MIDI: `AudioController` runs spessasynth against
`public/TimGM6mb.sf2` and fetches `/mfx/mfxNNN.mid`. That path was complete and
unused -- `public/mfx/` was empty, which is why the game had no music and why
the title screen 404'd on `mfx001.mid`.

Staying on it means no client changes, no new dependencies, ~1-2KB per track
instead of ~3MB, and no licence questions: every note here is generated by this
tool.

## Layout

| Path | What |
| --- | --- |
| `lib/smf.mjs` | Standard MIDI File writer (format 1, no running status) |
| `lib/smf-parse.mjs` | Reader, so the suite can verify emitted bytes |
| `lib/music.mjs` | Modes, degree->pitch, seeded RNG |
| `lib/score.mjs` | What tracks are written against: beats, degrees, loop length |
| `lib/figures.mjs` | Drone, arpeggio, percussion pulse |
| `lib/arrange.mjs` | The pad/texture/lead/drum arrangement most tracks share |
| `lib/render.mjs` | Descriptor -> score, and the master gain |
| `tracks/*.mjs` | One file per track |

Melodies, chord progressions and phrase placement are hand-written. The helpers
only fill in mechanical texture, so a track file reads as musical intent rather
than as parameters.

`arrange()` assigns channels (pad 0, texture 1, lead 2, counter 3, drum 10) so a
track can't accidentally put two voices on one channel -- a lead colliding with
its own accompaniment on a pitch leaves a note ringing until the sequencer
resets. Tracks 001-008 predate the helper and wire their parts by hand; they are
left alone because their output is blessed and byte-stable.

`TRIAD` in `lib/music.mjs` holds triads in *degree* space, so `TRIAD.iv`
resolves major in dorian and minor in aeolian with no work from the caller.

## Rules the suite enforces

- **Nothing sustains past the loop point.** The sequencer restarts at tick 0
  with `loopCount = Infinity`, so a note still ringing at the end is chopped
  mid-decay on every repeat. `score.part().note()` throws rather than allow it.
- **Every note is released, and no pitch overlaps itself on a channel.** A
  re-attack while a pitch is still sounding leaves the first note hanging.
- **Melodic pitches stay in the track's declared mode and in playable range.**
- **Output is byte-identical across runs.** Nothing may call `Math.random()`;
  use `createRng(seed)`.

## Loudness

`MASTER_GAIN` in `lib/render.mjs` is calibrated, not guessed: 1.25 puts the
title theme's peak at 0.243 against the game's sound effects at 0.37-0.82.
Sparse tracks additionally carry a per-track `gain` trim so they stay quiet
without vanishing. SF2 velocity maps to attenuation exponentially, so
**re-measure with `preview.mjs` rather than extrapolating** if you change it.

## Adding a track

1. Write `tracks/NNN-slug.mjs` exporting a descriptor (`id`, `slug`, `title`,
   `tonic`, `mode`, `bpm`, `bars`, `compose(score)`).
2. Add it to `tracks/index.mjs`.
3. `node --test "tools/musicgen/**/*.test.mjs"` -- the invariant suite picks it
   up automatically.
4. `node tools/musicgen/preview.mjs slug` and listen to it.
5. `node scripts/sync-editor-music.mjs` so the map editor's Music dropdown
   offers it. The pre-commit hook checks this for you (`music:parity`).
6. Point maps at it -- see below. Tracks carrying `usedBy: 'unassigned ...'`
   are deliberately not wired to anything; adding files costs ~1-2KB each and
   nothing plays until a map names the id.

## How map music actually gets set

**The AIO editor is the source of truth.** Its Map Editor has a Map Properties
dialog with Music and Music Control; it writes straight to the `origin-maps`
volume, recomputes the map's `rid` as a CRC32 of its contents so connected
clients bust their cache and refetch, and reoserv hot-reloads the file. That is
the only path that works against maps which exist on live but not locally.

**Set Music Control to "Stop different - Play repeat".** The editor defaults to
*play once*, which leaves a map silent for as long as a player stands on it.

The Music field is a named dropdown listing these tracks, generated into the
eomap-js fork by `scripts/sync-editor-music.mjs`. A map already carrying an id
the list doesn't know (a legacy value) shows as "N — unrecognised" and survives
a save untouched.

reoserv's `npm run assign-music` is a **bootstrap only**: it refuses to touch a
map that already carries a track, and needs `--force` to overwrite from its
table. Generated maps still get their track from the catalog's `musicId`.

> **Deploy order matters.** The `.mid` files are baked into the eoweb image, not
> served from a volume like maps/pubs/gfx. A music id only plays once eoweb has
> been redeployed with that track present -- otherwise the client 404s and the
> map is silent.

## Output is not in git

`public/mfx*` is gitignored like every other asset directory; the `.mid` files
are build output baked into the Docker image at deploy time. This tool is the
source of truth -- regenerate freely.
